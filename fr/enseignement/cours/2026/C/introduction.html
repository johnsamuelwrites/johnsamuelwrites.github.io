1.1. Programmation en C: Introduction

Travaux pratiques, projet et évaluation

  • Les travaux pratiques (TP) servent à construire la compréhension nécessaire pour programmer, déboguer et expliquer du code C.
  • Les TP ne font plus l'objet d'une demande de soumission systématique.
  • Il y a 3 groupes, chacun encadré par un intervenant.
  • Il est fortement conseillé de travailler en binôme.
  • Le travail de TP est évalué par l'examen écrit de TP (40 %), sur papier et sans documents. La partie théorique est évaluée séparément par le DS (60 %).
  • L'examen écrit de TP porte sur les travaux réalisés et leur compréhension, et sur la capacité à lire, corriger et justifier du code, y compris lorsqu'il a été généré par un outil d'IA.

1.1. Programmation en C: Introduction

Travaux pratiques: traces de travail

  1. Les TP ne sont pas tous à soumettre, mais il est recommandé de conserver une trace personnelle du travail réalisé.
  2. Votre dossier de travail peut comporter les éléments suivants :
    • Un fichier README.md contenant vos notes, erreurs rencontrées et corrections.
    • Un fichier CONTRIBUTORS.md listant les noms et prénoms des contributeurs.
    • Un répertoire src/ contenant les fichiers sources, identifiables par les extensions .c et .h.

1.1. Programmation en C: Introduction

Travaux pratiques: auto-évaluation

  1. Après chaque TP, vérifiez que vous pouvez expliquer le code sans ordinateur.
  2. Assurez-vous d'écrire ou de compléter vos notes au format Markdown lorsque cela vous aide à préparer l'examen écrit de TP.
  3. Le contenu conseillé du fichier README.md comprend :
    1. Rapport d'auto-évaluation pour le TP travaillé.
    2. Bibliothèques utilisées, y compris les bibliothèques standard.
    3. Références telles que les URL, pages de manuel ou assistants d'IA consultés.
    4. Indication du niveau de difficulté (facile, moyen, difficile).
    5. Erreurs rencontrées, messages du compilateur, tests réalisés et corrections apportées.

Liste de contrôle

Avant de considérer un exercice comme compris, vérifiez la liste de contrôle suivante :

  • ✅ Vous avez respecté les noms de fichiers tels que spécifiés dans chaque exercice des travaux pratiques.
  • ✅ Votre code est accompagné de commentaires appropriés pour expliquer la logique et la fonctionnalité.
  • ✅ Votre code peut être compilé sans générer d'erreurs, et dans la mesure du possible, sans générer d'avertissements.
  • ✅ Vous savez expliquer les pointeurs, allocations, conversions et appels système utilisés.
  • ✅ Si une IA a aidé à produire du code, vous avez vérifié chaque choix technique et corrigé les erreurs éventuelles.

1.1. Programmation en C: Introduction

Objectifs des travaux pratiques

  1. Comprendre la chaine de compilation en utilisant GCC (GNU compilation chain) : prétraitement jusqu’à l’exécution
  2. Travailler avec les bibliothèques standards et les appels de système d’exploitation (fichiers, les sockets réseau etc.)
  3. Comprendre les pointeurs et manipuler les buffers en utilisant les pointeurs
  4. Créer, compiler et exécuter un projet C
  5. Travailler avec les différents formats de données comme BMP
  6. Créer un simple programme client-serveur pour le transfert de fichiers et messages
  7. Exécuter les applications existantes sur la machine (e.g. GNU plot)
  8. Documenter une application en utilisant le format markdown (*.md)
  9. Tester une application
