4.1. Fonctions pures et effets de bord

Fonctions pures, effets de bord, immuabilité

  • Une fonction pure renvoie toujours la même sortie pour la même entrée, et n'a aucun effet observable en dehors de sa valeur de retour.
  • Un effet de bord : écrire dans une variable globale, modifier un paramètre à travers un pointeur, lire une entrée, afficher un résultat.
  • L'immuabilité : une valeur ne change pas après sa création ; on en produit une nouvelle.
/* impur : modifie le tableau de l'appelant */
void doubler(int t[], size_t n) {
  for (size_t i = 0; i < n; i++)
    t[i] *= 2;
}

/* pur : produit une nouvelle valeur */
int double_de(int x) {
  return 2 * x;
}

La seconde se teste sans contexte, se met en cache, et s'exécute en parallèle sans risque. La première non : c'est tout l'intérêt du paradigme.

4.2. Les expressions lambda

Les expressions lambda

  • Une expression lambda est une fonction anonyme qui peut être définie et utilisée dans des contextes spécifiques. Contrairement aux fonctions traditionnelles, les expressions lambda n'ont pas besoin de nom, ce qui en fait des fonctions "anonymes".
  • Elles sont couramment utilisées lorsque vous avez besoin d'une fonction rapide à usage unique.

Caractéristiques clés

  1. Anonyme : Les lambdas n’ont pas de noms explicites.
  2. En ligne : Elles sont définies directement dans le code environnant.
  3. Usage unique : Elles réalisent généralement une opération spécifique et courte.
  4. Fermeture : Elles peuvent capturer les variables du contexte dans lequel elles ont été définies.

4.2. Les expressions lambda

Syntaxe

La syntaxe générale d’une expression lambda ressemble à ceci :

(lambda (paramètres) => expression)

Ou dans de nombreux langages modernes :

(paramètres) => expression

Ici, les paramètres sont les entrées, et l’expression est l’opération effectuée lorsque la lambda est invoquée.

La fonction map est une fonction intégrée en Python qui applique une fonction à chaque élément d’une liste (ou d’un autre itérable) et renvoie une nouvelle liste avec les résultats. Dans cet exemple, une expression lambda est utilisée pour définir une fonction anonyme qui prend un élément x en entrée et renvoie son carré (x ** 2).

  • map est la fonction qui applique la fonction lambda à chaque élément de la liste nombres.
  • lambda x: x ** 2 est l’expression lambda qui définit la fonction anonyme. Elle prend un élément x en entrée et renvoie son carré.
  • nombres est la liste qui contient les éléments à traiter.
  • list est utilisé pour convertir le résultat de map en une liste. En Python 3, map renvoie un objet itérable, mais pas une liste.

7. Utilisation dans des fonctions d’ordre supérieur

Les lambdas sont très utiles dans les fonctions d’ordre supérieur, c’est-à-dire des fonctions qui prennent d’autres fonctions en paramètre ou qui en retournent.

Caractéristiques des fonctions d'ordre supérieur

  • Fonctions en tant que paramètres: Une fonction d'ordre supérieur peut accepter une ou plusieurs fonctions comme arguments.
  • Fonctions en tant que valeurs de retour : Une fonction d'ordre supérieur peut retourner une fonction.

4.3. Les expressions lambda en Python

7. Utilisation dans des fonctions d’ordre supérieur

Exemple : Utilisation avec reduce

Comment reduce fonctionne étape par étape :

  • Au départ, reduce prend les deux premiers éléments de la liste : 1 et 2.
    • La lambda est appelée avec acc = 1 et x = 2, donc 1 + 2 = 3.
  • Ensuite, reduce prend le résultat précédent (3) et le troisième élément de la liste (3).
    • La lambda est appelée avec acc = 3 et x = 3, donc 3 + 3 = 6.
  • Enfin, reduce prend le résultat précédent (6) et le dernier élément de la liste (4).
    • La lambda est appelée avec acc = 6 et x = 4, donc 6 + 4 = 10.

Le résultat final est donc la somme de tous les éléments de la liste : 10.

4.4. Fonctions d'ordre supérieur

map, filter, reduce

Une fonction d'ordre supérieur prend une fonction en paramètre, ou en renvoie une.

from functools import reduce
nombres = [1, 2, 3, 4, 5, 6]

carres = list(map(lambda x: x ** 2, nombres))   # [1, 4, 9, 16, 25, 36]
pairs  = list(filter(lambda x: x % 2 == 0, nombres))  # [2, 4, 6]
somme  = reduce(lambda a, b: a + b, nombres, 0)   # 21
  • map : transformer chaque élément — filter : en retenir certains — reduce : les replier en une seule valeur.
  • Aucune de ces trois n'écrit de boucle explicite : c'est le pas impératif → déclaratif.

4.4. Fonctions d'ordre supérieur

Et en C ?

C possède le mécanisme — le pointeur de fonction — sans la syntaxe ni les garanties.

/* map, version C */
void appliquer(int t[], size_t n, int (*f)(int)) {
  for (size_t i = 0; i < n; i++)
    t[i] = f(t[i]);
}

int carre(int x) { return x * x; }
appliquer(t, 6, carre);

C'est l'idiome de qsort. Ce que C n'a pas : les fermetures, l'immuabilité, une valeur construite plutôt que mutée. Un paradigme n'est pas une propriété du langage : c'est une façon d'organiser le calcul, que le langage rend plus ou moins confortable.

4.5. Types algébriques et filtrage par motif

Représenter « une valeur, ou une erreur »

En C, trois réponses coexistent, et aucune n'oblige l'appelant à vérifier : une valeur sentinelle (-1, NULL), un code d'erreur, ou errno. Les types somme, eux, font de l'échec un cas du type :

// Rust : le type dit qu'il y a deux cas possibles
fn diviser(a: i32, b: i32) -> Option<i32> {
    if b == 0 { None } else { Some(a / b) }
}

match diviser(10, 0) {
    Some(v) => println!("résultat : {v}"),
    None    => println!("division par zéro"),
}

Le compilateur vérifie l'exhaustivité : oublier un cas est une erreur de compilation (Python 3.10 : match/case). Rendre les états incorrects impossibles à écrire : le typage statique poussé jusqu'au bout.
